# Requirements: cookbook-route-deeplink

> Version: 1.0  
> Status: APPROVED  
> Last Updated: 2026-05-02

## Problem Statement

Пользователи должны открывать конкретные экраны книги по ссылкам из соцсетей, рассылок и QR-кодов. На мобильных устройствах ссылки должны вести в нативное приложение (deeplink / app link); в браузере — открывать веб-версию с тем же логическим маршрутом. Посетители веб-версии на телефонах должны видеть понятное предложение установить приложение, с кнопкой на магазин, релевантный их региону. Базовые URL и ссылки на сторы уже заданы в `.env`, их нельзя хардкодить в коде.

## User Stories

### Primary

**As a** читатель книги  
**I want** перейти по ссылке (HTTP или `cookbook://`) на конкретный раздел или страницу  
**So that** я попадаю на тот же контент в приложении или на сайте

**As a** посетитель веб-версии с телефона  
**I want** увидеть предложение установить приложение с правильным магазином для моей страны  
**So that** я могу установить приложение без поиска вручную

### Secondary

**As a** маркетинг / автор контента  
**I want** использовать стабильные, документированные URL вида веб-базы из `.env` + путь  
**So that** ссылки не ломаются при смене домена в конфигурации

## Acceptance Criteria

### Must Have

1. **Given** установлено приложение на Android/iOS  
   **When** пользователь открывает HTTPS-ссылку на контент (формат согласован со спецификацией и базой `WEBAPP_URL`)  
   **Then** система предлагает открыть приложение и приложение показывает нужный экран (App Links / Universal Links), либо открывается веб-версия при отсутствии приложения

2. **Given** приложение запущено  
   **When** вызывается URI со схемой `cookbook`  
   **Then** роутер приложения разбирает путь/параметры и отображает соответствующий экран

3. **Given** пользователь на **web** (Flutter Web)  
   **When** он переходит по прямому URL с путём (не только на главную)  
   **Then** после загрузки приложение показывает экран, соответствующий пути (без «застревания» на главной из-за отсутствия роутинга)

4. **Given** пользователь открыл веб-приложение в мобильном браузере  
   **When** прошла инициализация (и при необходимости определена страна)  
   **Then** показывается ненавязчивый UI (banner / bottom sheet / snack-style), предлагающий установить приложение, с primary-кнопкой на URL из `.env`, выбранный по правилам страны (см. спецификацию)

5. **Given** сборка с разными значениями `.env`  
   **When** приложение читает конфигурацию  
   **Then** `WEBAPP_URL`, `APPSTORE_URL`, `GOOGLEPLAY_URL`, `RUSTORE_URL`, `RUMARKET_URL` используются как единственный источник правды для соответствующих ссылок (без дублирования констант в коде)

### Should Have

- Возможность закрыть предложение установки и запомнить выбор на сессию или в `localStorage` (чтобы не спамить).
- Логирование (debug) неразобранных deeplink для доработки маршрутов.

### Won't Have (This Iteration)

- Полный OAuth / приглашения по deeplink с секретами в URL.
- Серверный редирект по стране (только клиентское определение региона или заголовки CDN при наличии).

## Constraints

- **Technical**: Flutter-проект `app/cookbook`; конфигурация через `.env` (в репозитории может быть пример; секреты не коммитить).
- **Platform**: Android App Links, iOS Universal Links, кастомная схема `cookbook`; Web — статический хостинг совместимый с GitHub Pages.
- **Dependencies**: Появление роутера (например `go_router`) и загрузки env на всех платформах, где нужны URL.

## Open Questions

- [ ] Точная матрица «страна → магазин» (РФ: RuStore vs RuMarket приоритет; СНГ; остальной мир: Google Play vs Apple только на iOS?). Зафиксировать в спецификации после решения продукта.
- [ ] Фактический формат путей контента (slug главы, id рецепта и т.д.) — синхронизировать с текущей/планируемой навигацией книги.
- [ ] В `.env` поле `APPSTORE_URL` сейчас дублирует Google Play — для iOS нужна реальная ссылка App Store перед релизом iOS.
